# تحديث الأوتوميشن القديم: منع التكرار وموعد نهاية العرض

[الرئيسية](../README.md) · [شرح التشغيل للنسخة المحمولة](SETUP.ar.md)

ده للنسخة الأصلية اللي بتشغّل Steam عن طريق SSH، ونوداتها اسمها **05 - Filter Offers** و**08 - Build Telegram Message**. لو بتستخدم النسخة المحمولة اللي فيها **03 - Run Steam Helper** و**04 - Build Notifications**، اتبع قسم تحديث النسخة المحمولة في آخر الصفحة بدل سكربت SSH.

## التغيير

- العرض ونفس الحالة بيتبعتوا مرة واحدة، من غير إعادة إرسال تلقائية بعد سبعة أيام.
- تغيّر حالة النتيجة أو الموعد المعلن يوصّل تحديثًا. تغيّر نص السبب أو رابط الصورة أو الوقت المتبقي لوحده مش بيكرر الرسالة.
- لو العرض غاب عن نتيجتي بحث ناجحتين متتاليتين وبعدها رجع، يتعامل كعرض جديد. غياب مرة واحدة مش كفاية عشان مشكلة مؤقتة في البحث متكررهوش.
- نهاية العرض بتتقرأ من بيانات Steam الرسمية المضمّنة في صفحة نفس اللعبة ونفس عرض التملك المجاني. مفيش تخمين من التاريخ المكتوب أو موعد خصم لعبة تانية.
- الرسالة بتعرض التاريخ والساعة بتوقيت القاهرة والمدة المتبقية وقت الإرسال. الرسائل القديمة مش بتتعدل كل دقيقة.
- لو الموعد غير متاح أو البيانات متعارضة، يظهر «موعد الانتهاء غير معلن».

## 1. وقف الجدولة مؤقتًا وخد نسخة

اعمل Deactivate/Unpublish للـworkflow مؤقتًا، واستنى أي تنفيذ شغال يخلص. صدّر نسخة من الـworkflow قبل تغيير الكود. سكربت التحديث بيعمل نسخة احتياطية من claim.cjs، ومش بيقرأ أو يغيّر auth.json.

## 2. تحديث استخراج موعد الانتهاء على السيرفر

افتح [سجل التحديثات](https://github.com/Ebnhussein/n8n-steam-free-games/commits/main/) وخُد SHA التحديث الكامل اللي هتثبته، أو استخدم SHA اللي جه مع تعليمات التحديث. استبدل `COMMIT_SHA` بنفس قيمة الـSHA الكاملة من 40 حرف في الأمرين:

```bash
curl -fL https://raw.githubusercontent.com/Ebnhussein/n8n-steam-free-games/COMMIT_SHA/scripts/update-legacy-expiry.py -o /tmp/update-steam-expiry.py
sudo python3 /tmp/update-steam-expiry.py --ref COMMIT_SHA
```

الإعدادات الافتراضية لنفس التركيب الأصلي:

| الإعداد | الافتراضي |
| --- | --- |
| مجلد السكربتات على السيرفر | `/srv/projects/n8n/steam-auth` |
| كونتينر التنفيذ | `n8n-steam-runner-1` |
| المجلد جوه الكونتينر | `/home/runner/steam-auth` |

لو تركيبك مختلف، استخدم خيارات `--root` و`--container` و`--container-root`. السكربت بيرفض تعديل claim.cjs لو مواضع الكود المعروفة مختلفة، وبيعمل `node --check` قبل التثبيت. لو فشل، متحاولش تستبدل السكربت بشكل عشوائي؛ راجع نسخة claim.cjs بدون ملف بيانات الدخول.

بعد نجاح التحديث، اختبر **بدون إضافة** باستخدام App ID فعلي لعرض موجود:

```bash
sudo -n flock -n /run/lock/n8n-steam.lock docker exec n8n-steam-runner-1 node /home/runner/steam-auth/claim.cjs APP_ID
```

هتلاقي في النتيجة `expiresAt` بصيغة UTC/ISO لو Steam موفّره، أو `null` لو غير متاح. App ID هنا مكان رقم اللعبة، مش نص يتنسخ كما هو.

## 3. استبدال كود نود 05

افتح [legacy-filter-offers.js](../workflows/code/legacy-filter-offers.js)، واختار **Raw** ثم انسخ محتواه كاملًا.

في n8n افتح **05 - Filter Offers**، واستبدل الكود كله. الوضع **Run Once for All Items**، وسيب `TEST_MODE = false` للتشغيل الحقيقي.

النود بتسجل غياب العروض حتى لو النتيجة صفر، لأنها موجودة قبل نود IF. سيب مسار false زي ما هو. رابط البحث في نود 04 لازم يفضل شامل الـDLC من غير `category1=998`.

## 4. استبدال كود نود 08

افتح [legacy-build-message.js](../workflows/code/legacy-build-message.js)، واختار **Raw** ثم انسخ الكود كله.

في n8n افتح **08 - Build Telegram Message**، واستبدل الكود كله. الوضع **Run Once for All Items**. الكود بيعتمد على اسم **05 - Filter Offers** زي ما هو.

نود تليجرام تفضل تقرأ:

| الخانة | القيمة |
| --- | --- |
| Photo | `{{ $json.photo }}` |
| Caption | `{{ $json.text }}` |
| Parse Mode | `HTML` |

مش محتاج تغيّر الكردنشلز أو تعمل تسجيل Steam جديد بسبب التحديث ده.

## 5. الاختبار الصحيح لمنع التكرار

احفظ وانشر/فعّل الـworkflow. أول تشغيل بعد التحديث ممكن يبعت العروض مرة واحدة لبناء السجل الجديد.

**اختبر المنع بتشغيل مجدول تلقائي مرتين**. تقدر تغيّر الجدولة مؤقتًا لدقائق مناسبة وتستنى تشغيلين، وبعدها ترجعها كل ساعة؛ متشغّلش تنفيذًا جديدًا لو القديم لسه شغال. نفس اللعبة والعرض والحالة مش المفروض يتبعتوا في التشغيل الثاني.

الضغط اليدوي على Execute workflow مناسب لاختبار الشكل، لكنه **مش بيثبت منع التكرار بين التشغيلات اليدوية**: n8n مش بيحفظ workflow static data للتجارب اليدوية. كمان وضع TEST/dry_run متعمّد إنه ما يسجلش التنبيهات باعتبارها تنبيهات حقيقية.

السجل بيتحفظ بعد نجاح التنفيذ المنشور. لو تليجرام فشل والتنفيذ كله فشل، السجل الجديد مش بيتحفظ. لو بعض الرسائل وصلت قبل فشل رسالة تانية، ممكن تتكرر الرسائل اللي وصلت عند إعادة المحاولة؛ ده مش نظام exactly-once لتسليم الرسائل.

## تحديث النسخة المحمولة من الريبو

وقف الجدولة، ثم من مجلد المشروع:

```bash
git pull --ff-only
docker compose build
docker compose up -d
```

تقدر تستبدل كود **04 - Build Notifications** بمحتوى [build-notifications.js](../workflows/code/build-notifications.js)، مع الاحتفاظ بالكردنشلز والـworkflow الحالي. أو تستورد ملف الـworkflow المحدّث وتعيد اختيار بياناتك، مع التأكد إن نسخة واحدة فقط مفعلة. راجع `dryRun` قبل النشر؛ الملف المستورد يبدأ بوضع التجربة.

لا تستخدم سكربت SSH على النسخة المحمولة؛ استخراج الموعد موجود في الخدمة الجديدة نفسها.
