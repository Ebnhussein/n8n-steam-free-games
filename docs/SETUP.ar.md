# دليل التشغيل الكامل — عربي

[الصفحة الرئيسية](../README.md) · [English](SETUP.en.md) · [حل المشاكل](TROUBLESHOOTING.md)

الشرح ده بيبدأ من n8n موجود عندك على سيرفرك، وينتهي بأوتوميشن بيشتغل كل ساعة. كل مستخدم بيشغّل خدمته الخاصة، ويسجّل حساب Steam بتاعه، ويربط بوت تليجرام بتاعه. مفيش حساب مشترك أو خدمة خارجية بتحفظ بيانات الناس.

> **النسخة تجريبية.** الاختبارات البرمجية بتستخدم بيانات تجريبية، ومش دليل على نجاح إضافة لعبة فعلية. نشر Docker واستيراد الـworkflow وتسجيل Steam في النسخة المحمولة لسه محتاجين تحقق على بيئة فعلية. ابدأ بوضع التجربة.

## 1. المتطلبات

| المطلوب | التفاصيل |
| --- | --- |
| سيرفر Linux | عليه Docker Engine وDocker Compose v2 |
| n8n موجود | مستضاف عندك على نفس جهاز Docker، وتقدر تستورد workflows وتعمل credentials |
| Git | لتحميل وتحديث المشروع؛ أو تنزّل ZIP من GitHub |
| حساب Steam | اسم تسجيل الدخول والباسورد والوصول لـSteam Guard |
| تليجرام | حسابك، وبوت جديد أو بوت موجود عندك |
| اتصال إنترنت | الخدمة تقدر توصل لـSteam، وn8n يقدر يوصل لـTelegram |

افتح **ترمينال السيرفر** وجرّب:

```bash
docker --version
docker compose version
git --version
```

لو أوامر Docker عندك بتحتاج `sudo`، استخدم مثلًا `sudo docker compose ...` بدل `docker compose ...` في الخطوات. متفتحش صلاحيات Docker socket لكل المستخدمين. لو Docker مش متثبت، اتبع [تعليمات Docker الرسمية](https://docs.docker.com/engine/install/) و[تعليمات Compose الرسمية](https://docs.docker.com/compose/install/).

صورة الخدمة مبنية على Node.js 22. المقصود دعم ARM64 وAMD64، لكن بناء وتشغيل الصورة على المعماريتين لسه محتاج تحقق. الملف حاطط **حد أقصى 512 MB RAM ونصف CPU** للخدمة؛ دي حدود استهلاك، مش قياس للاستهلاك المعتاد، وn8n استهلاكه منفصل.

الطريقة دي لـn8n المستضاف عندك، مش ربط مباشر بـn8n Cloud. الخدمة على شبكة Docker خاصة؛ متفتحهاش على الإنترنت عشان تربطها بكلاود.

## 2. تحميل وبناء المشروع

نفّذ على السيرفر، من المكان اللي بتحط فيه مشاريعك:

```bash
git clone https://github.com/Ebnhussein/n8n-steam-free-games.git
cd n8n-steam-free-games
docker compose build
```

باقي أوامر `docker compose` تتنفذ وإنت جوه مجلد المشروع. مش محتاج تثبّت npm أو Node.js على السيرفر بالطريقة دي؛ Docker بيجهّز المكتبات جوه الصورة.

## 3. توليد المفتاح وتسجيل Steam

### 3.1 مفتاح الربط

```bash
docker compose run --rm steam-helper node src/cli.cjs init
```

هيظهر مفتاح عشوائي. احتفظ بيه في مكان خاص؛ هنحطه في n8n في الخطوة 6. ده **مفتاح الخدمة المحلية**، مش Steam Web API key ومش توكن تليجرام.

المفتاح بيتحفظ جوه Docker volume اسمه المنطقي `steam_data`. لو شغّلت `init` تاني، بيعرض نفس المفتاح الموجود ومش بيغيّره. متصورش ناتج الأمر ولا تحطه في GitHub issues.

### 3.2 تسجيل الدخول التفاعلي

```bash
docker compose run --rm steam-helper node src/cli.cjs login
```

الترمينال هيسألك:

| السؤال | تكتب إيه؟ |
| --- | --- |
| `Steam account name` | اسم الدخول للحساب، مش اسم البروفايل أو رابطه |
| `Password (hidden)` | الباسورد؛ مش هيظهر وإنت بتكتبه |
| `Current MOBILE Steam Guard code...` | لو Guard من تطبيق الموبايل، اكتب الكود الحالي؛ لو بالإيميل دوس Enter |
| سؤال الكود التالي | الكود الجديد اللي وصلك بالإيميل، أو كود الموبايل المطلوب |

لو Steam Guard بالإيميل، سيب أول سؤال لكود الموبايل فاضي عشان تستقبل الكود الجديد وتكتبه في السؤال اللي بعده. وافق على أي طلب تسجيل دخول حقيقي من تطبيق Steam أو الإيميل. لو Steam حظر الدخول، حل الحظر من Steam نفسه؛ المشروع مش بيتجاوزه.

رسالة النجاح:

```text
Login saved locally. Your password was not saved.
```

الباسورد مش بيتحفظ. اللي بيتحفظ هو refresh token داخل `auth.json` بصلاحيات `0600` جوه الـvolume، ومش بيتحط في ملف الـworkflow. مدير السيرفر يقدر يقرأ الـvolume، فخلي النسخ الاحتياطية خاصة.

### 3.3 تشغيل الخدمة وفحص الدخول

```bash
docker compose up -d
docker compose ps
docker compose exec steam-helper node src/cli.cjs check
```

نجاح فحص Steam بيرجع:

```json
{"authenticated":true}
```

حالة `healthy` لوحدها معناها إن خدمة HTTP بترد، مش إن Steam مسجّل دخول. أمر `check` هو اللي بيفحص جلسة Steam وقراءة الملكية. لو هتسجّل تاني، وقف الخدمة الأول زي قسم الصيانة.

## 4. ربط n8n بالخدمة

### 4.1 اعرف الكونتينر الصح

```bash
docker ps --format 'table {{.Names}}\t{{.Image}}'
```

اختار اسم كونتينر n8n الرئيسي اللي بيشغّل المحرر والسيرفر، مش الـrunner ولا قاعدة البيانات ولا Redis. استبدل `YOUR_N8N_CONTAINER` باسمه:

```bash
docker network connect steam-free-games YOUR_N8N_CONTAINER
```

لو Docker قال إن الاتصال موجود بالفعل، يبقى الكونتينر متوصل. لو n8n شغال بعمال تنفيذ منفصلين، وصّل الـworkers بالشبكة كمان؛ نود HTTP بتتنفذ عليهم.

### 4.2 خلّي الربط دائم

الأمر اللي فات مناسب للتجربة، لكن إعادة إنشاء الكونتينر بتلغي الاتصال اليدوي. خد نسخة من Compose بتاع n8n، وادمج فيه الشبكة الخارجية:

```yaml
services:
  app:
    networks:
      - default
      - steam-free-games

networks:
  steam-free-games:
    external: true
    name: steam-free-games
```

بدّل `app` باسم خدمة n8n عندك لو مختلف. حافظ على الشبكات اللي مشروعك محتاجها؛ `default` هنا مثال. **متستبدلش ملف Compose كله بالمثال، ومتكررش مفاتيح `services:` أو `networks:` لو موجودة.**

أعد نشر n8n بطريقتك المعتادة، سواء Compose أو Coolify. شغّل خدمة Steam الأول عشان تكون شبكة `steam-free-games` اتعملت قبل نشر إعدادات n8n الجديدة.

### 4.3 اختبار اتصال اختياري

```bash
docker exec YOUR_N8N_CONTAINER node -e "fetch('http://steam-helper:3000/health').then(async r => { console.log(r.status, await r.text()); }).catch(e => { console.error(e.message); process.exitCode = 1; })"
```

المتوقع `200` ومعاها `{"ok":true}`. الاختبار ده للشبكة بس، ومش بيضيف ألعاب ولا بيعرض مفتاح.

## 5. استيراد الـworkflow

1. افتح n8n من المتصفح.
2. اعمل workflow جديد.
3. افتح قائمة الـworkflow؛ غالبًا علامة `…` جنب الاسم.
4. اختار **Import from File**، وحدد `workflows/steam-free-games.json` من ملفات المشروع اللي نزلتها.
5. سيبه غير مفعّل لحد ما تخلص الضبط. أسماء أزرار n8n ممكن تختلف حسب النسخة؛ Publish وActive/Activate متعلقين بالنسخة المحفوظة اللي الجدولة هتشغّلها.

النودات اللي هتلاقيها:

| النود | وظيفتها |
| --- | --- |
| `01 - Every Hour` | التشغيل كل ساعة |
| `02 - Manual Test` | تشغيل يدوي |
| `03 - Run Steam Helper` | طلب HTTP للخدمة بمفتاحك |
| `04 - Build Notifications` | تنسيق الرسائل ومنع التنبيهات المتطابقة في التشغيل المجدول |
| `05 - Has Photo?` | اختيار مسار صورة أو نص |
| `06 - Telegram Photo` | إرسال صورة اللعبة ومعاها النص |
| `07 - Telegram Text` | إرسال نص لو مفيش صورة من المصدر |

الملفات مفيهاش credentials حقيقية أو Chat IDs أو سجل تنفيذ أو دومين سيرفر شخصي.

## 6. إنشاء كردنشل الربط داخل n8n

1. افتح **03 - Run Steam Helper**.
2. عند **Authentication** اختار **Generic Credential Type**.
3. عند **Generic Auth Type** اختار **Header Auth**.
4. من اختيار الكردنشل، دوس **Create New Credential**.
5. سمّي الكردنشل مثلًا **Steam Helper — My Server**.
6. جوه الكردنشل املا الخانات دي واحفظ:

| الخانة | القيمة |
| --- | --- |
| **Name** | `X-API-Key` |
| **Value** | المفتاح اللي ظهر في الخطوة 3.1 |

اسم الكردنشل نفسه مجرد عنوان تختاره. لكن **خانة Name اللي جواه لازم تكون `X-API-Key`** لأنها اسم الهيدر اللي الخدمة بتستقبله.

ارجع للنود وتأكد من الإعدادات:

| الخانة | القيمة |
| --- | --- |
| Method | `POST` |
| URL | `http://steam-helper:3000/v1/run` |
| Authentication | Generic Credential Type → Header Auth |
| Credential | الكردنشل اللي عملته |
| Send Body | مفتوح |
| Body Content Type | JSON |
| Specify Body | Using JSON |
| JSON Body | `{"dryRun":true}` |
| Timeout | `300000` ملي ثانية؛ موجودة في الملف المستورد |

متختارش Basic Auth أو Bearer Auth، ومتحطش هنا توكن تليجرام أو refresh token بتاع Steam. لو مفيش اختبار اتصال للكردنشل العام، احفظه واختبر نود HTTP نفسها؛ نتيجة اختبار كردنشل عام مش بديل لاختبار الخدمة.

مرجع رسمي: [HTTP Request credentials](https://docs.n8n.io/integrations/builtin/credentials/httprequest/).

## 7. عمل بوت تليجرام والكردنشل بتاعه

### 7.1 إنشاء البوت

1. افتح [BotFather الرسمي](https://t.me/BotFather) في تليجرام.
2. دوس **Start**، وابعت `/newbot`.
3. اكتب اسم يظهر للناس، مثلًا **Steam Free Games**.
4. اختار username متاح وينتهي بـ`bot`، مثل اسم خاص بيك على شكل `my_steam_alerts_bot`.
5. BotFather هيبعت **توكن البوت**. احتفظ بيه بشكل خاص.
6. افتح البوت الجديد من الرابط اللي BotFather بعته، دوس **Start**، وابعت `hello`.

اسم البوت والـusername مش هما التوكن. لو التوكن اتسرّب، لغيه/جدده من BotFather وحدّثه في n8n.

### 7.2 حفظ التوكن في n8n

1. افتح **06 - Telegram Photo**.
2. عند **Credential to connect with** اختار **Create New Credential**، ونوعها **Telegram**.
3. سمّيها مثلًا **Steam Free Games Telegram**.
4. في **Access Token** حط توكن البوت اللي جالك من BotFather.
5. احفظ، ولو فيه اختبار اتصال اتأكد إنه نجح.
6. افتح **07 - Telegram Text** واختار **نفس الكردنشل**.

مش محتاج باسورد تليجرام الشخصي أو رقم الموبايل أو باسورد Steam في الكردنشل ده. لو خانة API base URL ظاهرة، سيب القيمة الافتراضية.

مراجع رسمية: [Telegram credentials في n8n](https://docs.n8n.io/integrations/builtin/credentials/telegram/) و[إنشاء بوت](https://core.telegram.org/bots/features#creating-a-new-bot).

## 8. معرفة Chat ID بتاعك

لو البوت جديد وn8n عندك متاح برابط HTTPS شغال، تقدر تجيب Chat ID من n8n نفسه، من غير ما تدي التوكن لبوت خارجي:

1. اعمل **workflow مؤقت منفصل**.
2. ضيف **Telegram Trigger**.
3. اختار كردنشل تليجرام اللي عملته.
4. اختار **Message** في التحديثات/الأحداث.
5. دوس **Listen for test event** أو **Test step** حسب النسخة.
6. بعد ما يبدأ يستنى، ابعت رسالة `hello` **جديدة** للبوت من تليجرام.
7. افتح ناتج الـtrigger بصيغة JSON، ودور على:

```json
{
  "message": {
    "chat": {
      "id": 123456789
    }
  }
}
```

الرقم هنا مثال؛ خُد رقمك من **`message.chat.id`**، مش `message.message_id` ولا رقم مستخدم البوت. لو رقم جروب/قناة سالب، خُده بعلامة السالب زي ما هو.

وقف الاختبار وامسح الـworkflow المؤقت بعد ما تخلص. البوت بيستخدم webhook واحد؛ متعملش الاختبار ببوت مربوط بـtrigger إنتاجي تاني. لو بوتك مستخدم بالفعل، استعمل Chat ID متأكد منه بدل تغيير الـwebhook. اختبار Telegram Trigger محتاج webhook HTTPS يوصل له تليجرام؛ الـworkflow الأساسي نفسه بيرسل رسائل ومش محتاج Telegram Trigger.

ارجع للـworkflow الأساسي واستبدل `YOUR_CHAT_ID` في **نودتي تليجرام** برقمك. لو هتبعت لقناة، لازم البوت يبقى عنده صلاحيات نشر مناسبة. الأفضل أول تجربة تبقى في شات خاص بينك وبين البوت.

## 9. التجربة والتفعيل الحقيقي

### 9.1 تجربة بدون إضافة

سيب JSON Body في نود **03** كده:

```json
{"dryRun":true}
```

اضغط **Execute workflow** من البداية. راجع ناتج **03 - Run Steam Helper**. لو مفيش عروض ممكن تلاقي:

```json
{
  "mode": "dry_run",
  "candidateCount": 0,
  "searchTotal": 0,
  "attempts": 0,
  "results": []
}
```

الأرقام بتتغير حسب العروض. `results: []` معناها مفيش رسائل هتتبعت، ومش معناها إن تليجرام بايظ. لو فيه عروض، راجع حالة كل واحدة والسبب.

لو عايز تختبر تليجرام لوحده ومفيش عروض: والـworkflow لسه غير مفعّل، افصل السلك الداخل لـ**07 - Telegram Text** مؤقتًا، وبدّل Text من expression لنص ثابت مثل `Steam bot connection test`، وشغّل النود. دي هتبعت رسالة حقيقية. بعد الاختبار رجّع الـexpression الأصلي `{{ $json.text }}` ووصّل السلك تاني قبل الحفظ.

### 9.2 تفعيل محاولات الإضافة

لما تكون مستعد إنه يحاول يضيف العروض فعليًا، غيّر JSON Body في نود **03** إلى:

```json
{"dryRun":false}
```

احفظ واعمل **Publish / Activate**. تقدر تشغّل يدويًا للتجربة فورًا، والجدولة هتشتغل كل ساعة بعد التفعيل.

`claimed` معناها اتأكدنا من الملكية. **`verification_pending` مش نجاح**. لو إضافة محتاجة لعبة أساسية مدفوعة ومش عندك، طبيعي تتمنع. [شرح الحالات](TROUBLESHOOTING.md#الحالات-بالعربي).

لو عندك أوتوميشن Steam قديم، اقفله قبل تفعيل الجديد عشان الاتنين ميشتغلوش على الحساب مع بعض. الخدمة الجديدة مستقلة، ومش بتمسح أو تعدّل إعدادات الـrunner القديمة.

### 9.3 الرسائل بتتصرف إزاي؟

- صورة ونص لو الصورة موجودة من Steam؛ غير كده نص بس.
- السعر السابق بنفس العملة اللي Steam رجّعها؛ لو مش متاح هيقول كده. موعد الانتهاء يظهر بتوقيت القاهرة مع الوقت المتبقي لحظة الإرسال، أو «غير معلن» لو مفيش موعد موثوق.
- الحاجة الموجودة في الحساب مش بيتبعت عنها تنبيه.
- نفس العرض والحالة والموعد بيتبعتوا مرة واحدة بعد **تشغيل مجدول ناجح**. لو الحالة أو الموعد المعلن اتغيروا يوصل تحديث؛ تغيّر السبب أو الصورة أو السعر أو العدّ التنازلي مش بيكرر الرسالة. غياب العرض عن نتيجتي بحث ناجحتين متتاليتين يسمح بتنبيه جديد لما يرجع.
- الاختبار اليدوي ممكن يكرر الرسائل لأن n8n مش بيحفظ static data للتنفيذ اليدوي.
- لو إرسال الرسالة فشل، التنفيذ يفشل؛ راجع سجل n8n. لو تليجرام نفسه مش متاح، مش هيقدر يوصّل تنبيه عن عطل تليجرام.

## 10. تفعيل تنبيهات الأعطال

1. استورد `workflows/steam-error-alert.json` كـworkflow تاني.
2. افتح **Telegram Error Alert**.
3. اختار نفس كردنشل تليجرام.
4. بدّل `YOUR_CHAT_ID` برقم الشات.
5. احفظ الـworkflow.
6. افتح **Settings** للـworkflow الأساسي، وبعدها **Error Workflow**.
7. اختار **Steam Free Games - Error Alert**، واحفظ وانشر/فعّل الأساسي.

Error Trigger بيتشغّل بواسطة n8n عند فشل تنفيذ تلقائي مرتبط بيه؛ مش محتاج جدول زمني لنفسه. لو الاختبار اليدوي كتب `Example Error Message` فده مجرد مثال لاختبار وصول تليجرام، مش عطل Steam حقيقي. أخطاء التجارب اليدوية تراجعها في سجل تنفيذ الأساسي.

فشل الدخول أو البحث أو قراءة الملكية ممكن يشغّل مسار الأخطاء. أما أخطاء لعبة واحدة، أو أساسية مدفوعة، أو ملكية لسه مش مؤكدة، فدي نتائج بتوصل في تنبيه اللعبة العادي. متظهرش التوكن في صور أو تقارير الأخطاء.

## 11. الصيانة والتحديث

### اللوجات وفحص الدخول

```bash
docker compose logs --tail=100 steam-helper
docker compose exec steam-helper node src/cli.cjs check
docker stats --no-stream
```

أمر `check` ممكن يجدد التوكن. متشغلوش في نفس وقت تشغيل الأوتوميشن. لو بتشخّص مشكلة توكن، وقف الجدولة والخدمة الأول واستخدم أمر فحص منفصل حسب حالتك.

### تسجيل الدخول من جديد

وقف الـworkflow مؤقتًا، وبعدها:

```bash
docker compose stop steam-helper
docker compose run --rm steam-helper node src/cli.cjs login
docker compose up -d steam-helper
```

لما الخدمة ترجع سليمة فعّل الـworkflow. وقفناها عشان تجديد التوكن ميحصلش في نفس وقت تسجيل الدخول الجديد.

### تحديث المشروع

وقف الجدولة مؤقتًا، ومن جوه مجلد المشروع:

```bash
git pull --ff-only
docker compose build
docker compose up -d
```

راجع حالة الخدمة وبعدها فعّل الجدولة. ملفات n8n المستوردة مش بتتحدث لوحدها مع Git؛ راجع [CHANGELOG.md](../CHANGELOG.md) قبل ما تستبدل الـworkflow، وراجع `dryRun` والكردنشلز بعد أي استيراد جديد.

### النسخ الاحتياطية ومسح البيانات

ملف الدخول والمفتاح محفوظين في `steam_data`. اعمل backup خاص بالطريقة المناسبة لسيرفرك، وحافظ على اسم مشروع Compose خلال التحديث عشان يرجع يستخدم نفس الـvolume. تغيير اسم المجلد/المشروع ممكن يخليه يختار volume جديد.

`docker compose down` بيحافظ على البيانات. **`docker compose down -v` بيمسحها**، وهتحتاج مفتاح وتسجيل دخول من جديد. متحطش backup أو `.env` أو auth.json أو كوكيز أو credential export في GitHub.

### لو هتبلغ عن مشكلة

ابعت نسخة المشروع، ونسخة n8n، ومعمارية السيرفر، وحالة النتيجة، ونص الخطأ بعد إخفاء البيانات الخاصة. استخدم نموذج البلاغات في المستودع وراجع [دليل المشاكل](TROUBLESHOOTING.md) الأول.
